0.13 Release Notes

Preparing 0.13. These notes describe the release being prepared. Download links still open the latest published release.

0.13 overview · 0.12 release history

PSF Guard 0.13 adds night schedules for your rigs, star measurements matched to N.I.N.A., integrated mosaics and GPU stacking. Run stacks and RC-Astro tools on another computer, then inspect the result with new color and pixel controls.

Upgrading

  • Allow time for rebuilds. The stacking engine changed, so each stack rebuilds once when next opened or refreshed. Older mosaic color previews without a solve of the integrated canvas are marked out of date; Build current set refreshes them from cached stacks.
  • Scoring defaults are shared on the server. The first editor to open PSF Guard after the update saves their own scoring defaults there, including built-in values. Everyone on the server then sees the same defaults, and only an editor can change them. A viewer's defaults are not copied. Review the defaults under Settings → Review → Grading & display.
  • Existing color previews keep their processing choices. New color previews use the Color setup marked as the default. New automatic narrowband recipes use an independent Star Stretch for RGB stars; saved setups keep their existing Auto MTF rendering until you switch.
  • Existing databases keep their settings. Quality-analysis and calibrated-copy settings keep their previous values. New databases inherit the shared defaults. Review them in Settings → Review → Grading & display and Settings → Processing → Calibration.
  • Star measurements refresh on the next quality scan. After updating, PSF Guard measures affected frames again using the new detection settings. Until then, scoring excludes their earlier scan values. Review Star detection under Settings › Review › Grading & display. PSF Guard remains the default source for star counts and HFR; choose Stars and HFR in Scoring to use N.I.N.A.'s measurements instead.
  • Update workers with the server. Install the same PSF Guard release on each worker. Stack builds stay on the server until you choose otherwise. WBPP runs stay on the server.
  • Direct Target Scheduler access remains deprecated. Existing direct connections still work in 0.13. For a new connection, open Settings → Databases & rigs → New / import and choose Import a local TS file or Use the PSF Guard Sync plugin. A later update will create a PSF Guard catalog for existing direct connections and keep captures, plans and grades in sync with Target Scheduler. Separate catalogs let us add features to PSF Guard and support new Target Scheduler versions. This automatic migration is not part of 0.13. If you are upgrading from 0.11, also read the 0.12 upgrade notes.

Plan each rig's nights

  • Open Rigs › Nights to compare clear dark hours, the Moon and planned work across your rigs. Select a night to see the predicted Target Scheduler or Director schedule, then choose a block to see why the scheduler selected it. Tonight's schedule starts from now. Targets that cannot run that night appear under Not this night, with a reason. Night planning and Director controls are in early beta; schedules are estimates.
  • Compare nearby sites together in the Nights grid. Rigs whose sites are within one degree in latitude and longitude share a group and a row of Cloud, Dew and Moon bars. They show cloud cover, how close the air temperature is to the dew point, and when the Moon is above the horizon. Hover for cloud cover, moonrise, the Moon's highest point and moonset.
  • Each filter run in a night schedule shows the minimum separation between the Moon and its target. The angle is dimmed when the Moon stays below the horizon. Select a target block to see each filter's minimum Moon separation and highest Moon altitude. Below the cloud band, a Moon strip shows its rise, highest point and set; brighter shading means a higher or more fully lit Moon.
  • The Live table has moved from Sky to Rigs › Live. Its Tonight column opens each rig's night schedule. Live on Sky still draws each reporting rig at its pointing position.
  • Mark nights Available, Not available, or Limited to specified hours for one rig or every rig at a site. Set the site's Time zone in Settings › Presets › Sites for entering and displaying marks and overrides. Marks change the predicted schedule; they do not stop or control a rig.
  • To use cloud forecasts, open Settings › Presets › Sites, edit a site, and choose Open-Meteo or MET Norway under Forecast. Set the maximum cloud cover that counts as clear. Forecasts are off by default. Enabling one sends the site's location, rounded to about 1 km, to the provider. A manual site mark overrides its forecast; a rig's own mark still applies. Nights with no clear dark hours appear red, including nights clear only in daylight. Forecasts change planning estimates, not the rig's safety controls.
  • Site forecasts now include temperature, dew point and humidity when the provider supplies them. To exclude hours close to the dew point, open Settings › Presets › Sites, edit a site, and set No imaging within under Weather forecast. For example, 2 °C excludes hours when the air temperature is 2 °C or less above the dew point. Leave the field blank to ignore dew. A drop icon marks nights shortened by this limit; the timeline shows a dew band and lists the affected hours. These forecasts change planning estimates only; they do not stop a rig.
  • For a Director rig, click Edit night to move or pin target blocks, exclude work, set a plan order or hold the rig. Review the changed schedule, then click Save changes. A running session finishes its current exposure and receives the overrides at its next check-in. Overrides only restrict the existing program and expire at the end of the observing night.
  • For a Target Scheduler rig, open Target Scheduler settings, then click Change settings to change project priorities or activate and deactivate projects and targets. Review the schedule, then click Save changes. Saving requires editor access and database management. PSF Guard updates the rig's database and, for a synced catalog, its Target Scheduler file too. These settings apply to every night until changed again. A conflicting edit prevents the affected save. Mode in rig setup selects Target Scheduler or Director; until set, PSF Guard infers the mode from the rig's reports. Pairing the Director plugin sets the rig's mode to Director.
  • Visibility in a plan's workspace now includes marks and forecasts in its estimate. For an activated plan, it also predicts a completion night within the next 14 nights using the rig's schedule and other assigned plans.
  • The server saves computed night plans and refreshes them when their inputs change. Updated shows when the displayed plans were computed; Compute again refreshes them. Computation appears in the header's job list. The MCP tool get_night_plans gives agents the same plans.

See Night planning.

Choose star measurements for grading

  • The quality scan can match each rig's N.I.N.A. detector settings. Open Settings › Review › Grading & display › Star detection to set the shared Default or a rig override. Choose Detector, Sensitivity, Noise reduction and Hocus Focus version, then click Save star detection. The defaults are Auto, High, None and 4. Auto selects Hocus Focus when N.I.N.A. 3.2 or earlier recorded an FWHM; otherwise it selects N.I.N.A.'s detector.
  • Under Import N.I.N.A. profile, import the autofocus crop, brightest-star count, autostretch and Hocus Focus options from a profile file. Choose All frames or Frames from a date, click Read file, then Import profile. Sync and Director plugins also record profile settings during capture. A frame before the first dated record uses the earliest record; later dated records still apply after an All frames import. If the settings changed over time, import each profile with the date its settings first applied.
  • Image Information shows both N.I.N.A. and PSF Guard measurements. Cards show the value used for scoring, marked N or P. Choose Stars and HFR in Scoring, or Measured by under Settings › Review › Grading & display › Sequence scoring, to select the source for Max HFR, Min stars, relative comparisons and the Stars and HFR cutoff. PSF Guard remains the default. Previously the limits used PSF Guard's values while views showed N.I.N.A.'s. Reject reasons now identify the source and show HFR to two decimal places.

See Star measurements and scoring.

Stack on the GPU and follow builds

  • Watch a channel's in-progress stack in Stacks, with a live preview updated about every five seconds. The finished preview replaces it when processing completes; completed FITS downloads remain separate during a rebuild.
  • Stack previews now use a supported GPU: Metal on a Mac, Vulkan on Linux and Direct3D 12 on Windows. Debayering, star detection, resampling, the live stack and the final pass run there. On an Apple M4 Max, 35 frames of 26 megapixels stacked in 5–6 seconds instead of 12. Computers without a supported GPU, and frames under about a million pixels, stack on the CPU as before. To choose which passes run on the GPU, open Settings → Performance → GPU. With Use the GPU off, all stacking work stays on the CPU, including artifact searches and the channel alignment of color previews.

See Stack previews.

Build integrated mosaics

  • Build one integrated mosaic per channel in Stacks, then compose RGB, LRGB and narrowband color from those mosaics. Frames keep their calibration sessions and align against overlapping panels. Incomplete mosaics identify panels with no aligned frames. Local background normalization also matches panel backgrounds through Seiza to reduce seam lines.
  • Mosaic color calibration now solves the integrated canvas instead of looking for a single reference-frame solve. RGB, LRGB, RGB-star and OSC calibration reuse that pixel solve. Older uncalibrated previews are marked out of date; Build current set refreshes them from the cached stacks.
  • Mosaic stacks prepare several frames at once on machines with less memory. Each frame in preparation is sized for the frame and the part of the canvas it covers, instead of the whole canvas. With a 12.8 GiB budget, a four-panel mosaic of 88 megapixels prepares three frames at once instead of one.
  • Mosaic SNR plots report canvas coverage and mean pixel depth. They keep each checkpoint's measured signal and no longer apply same-field forecasts or plateau/degrading verdicts to frames covering different sky areas. Saved mosaic plots use the corrected interpretation without rebuilding.
  • A live stack image replaces the waiting placeholder, so mosaic previews no longer display a second, full-height spinner area beneath the image.

See Mosaic builds.

Run processing on workers

  • Run a worker from the PSF Guard app on macOS or Windows. Open Settings › Performance › Workers › Worker on this computer, enter the Server address and Worker token, then click Save worker settings and Start worker. The worker continues running in the menu bar or system tray after you close the window. Start worker at login starts it when you log in. Opening PSF Guard while its window is open brings that window forward instead of starting a second copy.
  • Run a worker as a Windows service to process tasks before anyone logs in. Open Settings › Performance › Workers › Worker on this computer, click Save worker settings, then run psf-guard-cli worker-service install in PowerShell opened as administrator. Run the command again after changing settings or updating PSF Guard to update and restart the service. Desktop worker controls do not control the service.
  • Run a worker as a Linux service. The Fedora RPM and the Debian package install a psf-guard-worker systemd service without enabling it. Enter the server's address and a worker token in /etc/psf-guard/worker.conf, then run sudo systemctl enable --now psf-guard-worker. On Debian, copy /usr/share/doc/psf-guard/worker.conf.example to that file first.
  • Build stacks on another computer. Start a worker with --work stack, then choose Workers first or Workers only for stack builds in Settings › Performance › Workers. Each channel stacks there from the frames, masters, checkpoint and settings the server would use. Mosaics stack there too. Each channel's card shows which worker stacked it, and its Live stack preview shows the worker's running image. Stack builds stay on the server unless you choose otherwise.
  • Run RC-Astro tools on another computer. Add a worker in Settings › Performance › Workers, then run psf-guard worker --server … there with its token. The worker runs BlurXTerminator, NoiseXTerminator and StarXTerminator for stack previews, color previews and narrowband stars, and the processing panel shows where each tool runs. A worker accepts every tool it has, or the ones --work lists, and runs up to --slots steps at once. Choose under Where work runs whether RC-Astro runs on workers first with this server as the fallback, on workers only, or on this server only. Files go through the server, or, with --files shared, through a folder the worker and the server share.
  • Worker on this computer shows the local worker's settings and status; Workers for this server lists connected workers. The controls explain task types, concurrent tasks, temporary files and saved tokens. Tray status distinguishes waiting for a connection from waiting for tasks.
  • Windows worker services can now read their saved settings and start successfully. Reinstalling the service also repairs permissions left by an earlier installation and waits for the stopped worker process before replacing its executable.

See Workers.

Compose color and control stars

  • Color processing now follows numbered, expandable steps from input preparation to RGB finishing. See color and RGB-star branches separately, inspect the resolved star policy, and edit saved setups with consistent field fonts and spacing. Emission amounts and star reduction appear where they run in the pipeline; closing a step preserves its edits.
  • Narrowband previews can reduce the restored RGB stars independently of BXT. Adjust Processing stack → Combine and restore stars → RGB star reduction to make stars smaller and fainter while preserving their color and the starless nebula. Zero preserves the current result. BXT sharpening and halo controls remain configurable.
  • Combined color previews validate held-out stellar pixel profiles and can explicitly match continuum PSFs with Gaussian broadening. Reports show core/halo errors and the changed resolution. Narrowband controls also offer star exclusions for balance statistics and green-excess reduction before RGB stars are restored. Optional calibrated-response exports retain signed line flux, exact source provenance and uncertainty assumptions.
  • RGB-star previews now honor the selected Gaia settings and separate their SXT caches by those settings. RGB + emission and LRGB + emission builds explain when an inherited SXT step cannot run. Clearing the optional OIII B/G ratio returns to measured photometry.
  • Narrowband previews can sharpen their RGB star branch with BlurXTerminator before star extraction. Open Processing stack → Process linear color → RGB star processing.
  • Custom RGB + emission, LRGB + emission, and Narrowband + broadband structure cards fit and subtract continuum on aligned linear inputs. Automatic, Manual and Off controls retain signed residual downloads and show per-line fit results. Failed natural-color lines are omitted with a warning; a failed mapped line keeps the previous preview available.
  • New narrowband color cards offer automatic SHO/HOO selection, a shared H-alpha stretch, and background-protected OIII/SII balance. Choose Stars → Automatic to use RGB stars when the sources and StarXTerminator are available, with an explained fallback to narrowband stars. Exact RGB sources can use different exposures under the card's Custom combination. Existing previews keep their saved palette and processing.
  • Automatic stack refreshes now compose a target's first color preview once its channels are stacked, as a build you start does. New color previews start from the Color setup marked as the default. PSF Guard adds one named Default with the current pipeline. To use another pipeline, open Settings → Presets → Processing setups and click Make default on a Color setup, or save your changes over Default. Color previews you already have are not changed.
  • New automatic narrowband recipes stretch the linear RGB stars independently with a SetiAstro-style Star Stretch. Lower the amount in Combine and restore stars to keep stars fainter. Saved setups keep their existing Auto MTF rendering until you switch.
  • Narrowband cards show a visible ✨ Stars label beside the star-policy selector.
  • Configure StarXTerminator separately for the linear nebula and RGB-star branches in Process linear color. Finished compositions retain the cached linear starless/stars outputs, and display blend amounts reuse the SXT runs.
  • Set the processing memory budget in Settings → Performance → CPU & memory → Processing memory. Color and stretch errors show the estimate and current budget, with the setting to adjust it.
  • Color composition memory estimates now follow what a composition uses. The estimate counts each source channel and the composition's largest step, instead of adding every step. It includes an RC-Astro tool's own memory when the tool runs on this server. SHO with RGB stars on a 90-megapixel mosaic is estimated at 22 GiB instead of 26 GiB with StarXTerminator on this server, about what the two use together, and at 12 GiB when a worker runs StarXTerminator. RC-Astro on the color channels is estimated higher than before when it runs on this server, because its memory is now counted.

See Color processing.

Inspect stacks and measure pixels

  • The stack inspector fills the browser or app window, with the image beside a sidebar for details, available FITS downloads, Sky context, artifact search, shortcuts and zoom controls. The calibration master inspector uses the same layout. Both sidebars are narrower to leave more room for the image.
  • Stacks now offer the image viewer's analysis tools. Sky context plate-solves the stack's own pixels, starting from its frames, and draws objects in the field over the image. S marks stars with their HFR, and P opens the PSF view.
  • The image viewer and the stack inspector can show the pixel under the pointer. Turn on Value or RA/Dec, or press M or R, to see the pixel's position, its linear value from the file (one per channel of a colour stack), and its right ascension and declination from the plate solution, in a box that follows the pointer. PSF Guard reads only the pixels near the pointer, so a large stack does not have to load.
  • In the desktop app on Windows and Linux, F11 puts the window into full screen and back. On macOS, use View → Enter Full Screen or the window's green button.

See Stack inspection.

Find settings and share defaults

  • Settings lists databases directly in the left pane, with New / import for adding a database. Select a database to open Rig setup, Database & files, Import or Sync in the same navigation. Shared Sites are under Presets. Sync consistently calls its local and remote stores databases.
  • Quality analysis is under Review → Grading & display; calibrated-copy pairing is under Processing → Calibration. Both offer shared defaults and database overrides. Your configured databases keep their choices as overrides; newly added databases inherit shared defaults. AstroBin filter maps are beside shared AstroBin defaults under Exports & integrations → AstroBin.
  • Database overrides use the same controls as Calibration rig overrides. Inherited values align with their override buttons. Each database has an Import page with directly editable scan rules, automatic-import settings and previews. Creating a database from image folders offers the same exclusion patterns and scan filters before the first import.
  • Import uses saved filters by default. Expand Scan rules to edit them; saving closes the editor again. The scan filters for a new database start collapsed too. Long folder paths wrap within the manual import preview on phones.
  • Settings uses a compact header with Close and, in the desktop app, Open logs, leaving more room for the selected page. Each form keeps its own Save controls. Restart server appears with a saved port change or server startup error; folder changes keep Restart now beside the folders. Restart controls stay disabled while forms have unsaved edits.
  • Settings groups related pages in a desktop sidebar and a compact phone selector. Find GPU controls under Performance, exposure templates and processing setups under Presets, and export defaults, PixInsight and AstroBin under Exports & integrations. Existing settings and shortcuts are preserved. Settings asks before switching pages with unsaved edits. See Settings navigation.
  • In the Settings sections Exports & integrations → PixInsight, Processing → Stacking → Stack previews, Performance → CPU & memory → Processor use and, in the desktop app, Server & access → Server, fields no longer appear blank, or show an Automatic port, for a moment while Settings loads. When the server reports new values, fields you have not edited update to match, and a field you are editing keeps what you typed. In PixInsight, Check again now updates the executable and WBPP runs folder.
  • A plan's scheduling limits on its Rigs tab, and a rig's planning site and Target Scheduler limits under Rigs, no longer appear empty or marked unsaved for a moment when they load. A collaboration connection's Automation tab shows the saved choices at once instead of unticked boxes. Stack with WBPP shows the project's process folder at once. Fields you have not edited now follow newer values from the server; your edits stay until you save or discard them.
  • When someone else changes a rig's planning site or Target Scheduler limits while you edit them, Save rig profile no longer overwrites their change. PSF Guard saves the rest of the rig profile and explains that the planning site and Target Scheduler limits changed. Click Reload to load their values in place of your planning site and Target Scheduler limit edits. Reload rig profile keeps those edits when nothing changed on the server.
  • Automatic stack refreshes now score with the server's scoring defaults, the same values every view starts from. Stacks that showed Out of date — scoring settings changed after an automatic refresh are rebuilt with the defaults on the next automatic refresh, and stop showing it. Saving new defaults in Settings → Review → Grading & display rebuilds stacks scored another way when automatic previews are on.

See Settings navigation and scope.

Calibration and image compatibility

  • External flat masters at another gain, a new setting in Settings › Processing › Calibration › Matching and in each rig's settings, lets a flat master from other software calibrate lights shot at another gain or offset. Use it only when the master’s own flat darks were subtracted (recorded as DARKSUB) and the camera’s normalized flat does not change with gain, such as suitable gain-0 flats for gain-100 lights. It is off by default. When gain or offset is the only reason PSF Guard refuses a master, the refusal message identifies this setting.
  • A multi-session stack keeps lights that use different external masters in separate calibration sessions, even when they match the same raw frames. Existing masters, grades, flat groups and stacks keep their results through the calibration-library update and do not rebuild because of that update.
  • Plate solving starts from the solution PixInsight stores in an XISF frame. PixInsight keeps a plate solution as the file's own properties, not as FITS WCS keywords, so PSF Guard missed it and started from the frame's other pointing headers. It now reads the solution as it reads a solved FITS frame's WCS.

See Calibration libraries.

Import masters and leave out stacks

  • PSF Guard recognizes calibration masters made by seiza master, including older files whose type is recorded only in SEIZAMST. They enter the calibration library and follow the External masters policy under Settings › Processing › Calibration › Matching.
  • To repair Seiza masters previously imported as lights, select the database in Settings, open Import, click Preview import, then Import N frame(s). This manual import adds them to the calibration library; automatic import does not reread them. In the Library, open each Unknown Target project containing only those masters, open Edit project, and click Delete project.... This removes the light records and keeps the source files. Project deletion requires an editor account and a server started with --allow-database-management.
  • Imports now skip stacks and report how many were skipped; remote uploads refuse stacks. Previously a stack with a header such as NCOMBINE = 40 could enter the catalog as a light. Existing stack records remain in the catalog. An empty Include only scan rule now shows All files, replacing the misleading LIGHT placeholder.

See Importing images.

Storage and reliability

  • Volume usage limit now works on Windows as well as macOS and Linux. When a volume exceeds its limit, PSF Guard deletes least-recently-viewed previews first, then stack resume checkpoints at least a day old, then rebuildable calibration masters unused for a week. Disk use under Settings › Storage & backups › Folders & limits now shows Windows volumes.
  • On macOS, saving to an SMB network share now works when the share refuses a full sync. PSF Guard falls back to a plain sync instead of failing with Operation not supported (os error 45). This fixes affected saves of masters, stacks, uploads, WBPP work files, backups and settings.
  • FITS downloads in stack processing use compact controls with a download icon and explicit labels. Long labels wrap to fit narrow panels.
  • Save storage limits, folders, and WBPP retention together with Save storage settings. WBPP shares the Limits and Folders sections with the other storage options.
  • Manage WBPP work files under Settings → Storage & backups → Folders & limits: choose a dedicated folder and volume usage limit, remove intermediates before masters, and set separate retention periods. Intermediates default to seven days and masters to 90 days; Keep WBPP masters forever protects masters from cleanup. Active runs, downloads, and master copies are protected, and saved process masters and imported stacks remain separate.
  • Volume usage limits now accept every whole percentage from 0% through 100%, including values below 50%, for the cache, stacks, calibration masters, and WBPP.

Fixes already shipped in 0.12

This release includes the 0.12.4 fixes and the 0.12.5 renamed-file fixes. Those updates let the server start with missing image folders, keep renamed files matched to their frames in standalone and synced catalogs, add Merge renamed lights, check flat age against the nearest contributing flat, fix stale processing results and Settings scrolling, and update zstd for four memory-safety advisories.
