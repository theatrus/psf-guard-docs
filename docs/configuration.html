Configuration and API

The JSON registry lists catalogs and holds the choices made in Settings; the server's TOML file sets ports, caches and grants at start. The REST API exposes what the UI does.

Catalog registry

The server can serve many catalogs, each a database with Target Scheduler's tables. Their list lives in a JSON registry, not in the TOML file:

PlatformRegistry
Windows%APPDATA%\psf-guard\config.json
macOS~/Library/Application Support/psf-guard/config.json
Linux~/.config/psf-guard/config.json
Docker/data/config/psf-guard/config.json

psf-guard server <db> <dirs...> registers that database on first run and reuses it afterwards. Settings and the /api/databases endpoints edit the same list. --registry /tmp/scratch.json runs a session that leaves your real list alone. N.I.N.A.'s scheduler database on Windows is %LOCALAPPDATA%\NINA\SchedulerPlugin\schedulerdb.sqlite.

{
  "id": "archive",
  "name": "Archive",
  "db_path": "/data/archive.sqlite",
  "image_dirs": ["/data/images"],
  "export_dir": "/data/stacking-exports",
  "process_dir": "/data/_Process"
}
  • export_dir (Server export directory under Settings → Databases → Edit) turns on server-side exports into that folder. The browser picks a project, target and layout, never a path. Empty turns them off.
  • process_dir (Process directory) is where a WBPP run may save its masters beside your finished work. See WBPP Runs.

Settings saves server-wide choices in the same file: processor shares, storage folders and disk limits, stacking, calibration matching, export defaults, AstroBin filter IDs, PixInsight, and Remote PSF Guard peers. A peer's key is kept in the clear there, so protect the file.

Files beside the registry

PSF Guard keeps its other state next to the registry. With a registry named something other than config.json, each file takes the registry's name as a prefix: catalogs.json gets catalogs.auth.json.

FileHolds
auth.jsonBrowser users and API tokens, as hashes. See Server Accounts.
director-meta.sqliteThe planning store: plans, framing, rigs, sites, exposure templates
config.jobs.jsonThe job queue, kept across restarts. See Storage & Performance.
collaboration-credentials.jsonAstroCollab agent tokens, in plain text, mode 0600 on Unix and a user-only ACL on Windows. See Collaboration.
Keep the config folder writable only by the PSF Guard user, and leave collaboration-credentials.json out of backups you share and diagnostic bundles.

Planning store

Planning is on for every server. Its store, director-meta.sqlite, sits beside the registry, and the desktop app uses the same place. A server started without --allow-database-management plans read-only over its catalogs: plans, framing and rig profiles can be drafted, but activation, pushes and Target Scheduler edits answer 403, and nothing is written into a rig database.

# Keep the planning store somewhere else
psf-guard server --allow-database-management \
  --director-meta /srv/psf-guard/director-meta.sqlite

--director-meta needs --allow-database-management. Its folder must exist. A missing file is created; an existing file must be a planning store, never a catalog or another SQLite database. Back the store up with an SQLite-aware tool before an upgrade, and never copy a live main file without its WAL. See Planning.

Offline sky maps

Framing can draw on N.I.N.A.'s whole-sky caches with no network. Install one into the server's cache:

psf-guard sky-maps install full --cache-dir /path/to/cache               # DSS, 3.3 GB
psf-guard sky-maps install nsns-ohs --cache-dir /path/to/cache           # NSNS SHO, 1.4 GB
psf-guard sky-maps install nsns-ohs-starless --cache-dir /path/to/cache  # starless, 0.5 GB
psf-guard sky-maps list --cache-dir /path/to/cache
  • Sets land in <cache>/director/sky-maps/. A running server offers a new set within half a minute.
  • install also takes a zip URL. A folder copied from a rig's own %LOCALAPPDATA%\NINA\FramingAssistantCache works too: drop it under sky-maps/.
  • In Docker the default ./cache is /data/cache: docker exec psf-guard psf-guard sky-maps install full.
  • An offline set stands in for its online survey: the DSS set for the DSS2 colour plates, the SHO set for the online NSNS SHO layer. The online layer stays a click away.
  • The maps carry their own licences; the NSNS sets are CC BY-NC-SA. The framing view shows the attribution.

See Framing.

Seiza catalogs and plate solving

PSF Guard finds Seiza's catalogs the way Seiza does. Data installed with seiza setup or under Settings → Catalogs is found on its own. Name another bundle with the SEIZA_CATALOG_DIR environment variable or the top-level astrometry block in the registry:

"astrometry": {
  "data_dir": "/path/to/seiza-data",
  "satellite_elements": "historical-or-active.tle"
}

Blind solves use the blind index beside the star catalog. A blind_index setting or SEIZA_BLIND_INDEX still chooses another. Restart PSF Guard after changing the variable or the block. See Sky Context & Solver.

Docker

The image keeps everything it writes on the /data volume. It sets XDG_CONFIG_HOME=/data/config, so the registry and the files beside it live in /data/config/psf-guard; SEIZA_CATALOG_DIR=/data/seiza, so catalogs installed in Settings stay; and works in /data, so the default cache is /data/cache. A redeploy or an image update keeps all of it. See Installation.

Server TOML file

cp psf-guard.toml.example psf-guard.toml
psf-guard server --config psf-guard.toml
[server]
port = 3000
host = "0.0.0.0"
cors = true
# Shares of the logical cores. Settings → Performance overrides both.
#scan_worker_ratio = 0.5
#background_worker_ratio = 0.25
#preview_format = "png"        # or "jpeg"
#preview_jpeg_quality = 88     # 50–100
#preview_color = true          # colour by default for OSC frames
#keep_failed_uploads = false

[server.auth]
session_hours = 168
# Omit to follow the browser's HTTP or HTTPS scheme.
#secure_cookie = true
allow_read_only_compute = false

# Optional plain-text notice under the header
[server.banner]
title = "Demo site"
message = "This public demo uses sample data. Changes may be reset."
link_text = "Learn about PSF Guard"
link_url = "https://psf-guard.com/"

[cache]
directory = "./cache"   # fixes the cache; omit it to choose one in Settings
#stack_directory = "/mnt/nas/psf-guard/stacks"          # default: the cache
#calibration_directory = "/mnt/nas/psf-guard/masters"   # default: the cache
file_ttl = "5m"         # 30s, 5m, 1h, 2h30m, 1d ...
directory_ttl = "5m"

[pregeneration]         # optional background preview warming
enabled = true
screen = true           # 1200 px previews
large = false           # 2000 px previews
#workers = 4
KeyDoes
scan_worker_ratioShare of cores for work you wait on (default 0.5)
background_worker_ratioShare for background work (default 0.25). See Processor use.
[cache] directoryThe cache. Naming it here fixes it, so Settings cannot move it.
stack_directory, calibration_directoryFolders for stacks and masters. See Storage.
file_ttl, directory_ttlHow long file and folder listings are cached
[server.auth]Session length, cookie policy, and whether viewers may start compute. See Server Accounts.
[server.banner]A notice under the header. Plain text; set both link fields or neither, with http:// or https://.
keep_failed_uploadsKeep a refused remote upload's staged file in the receive folder, named in the log

Command-line options win over the file. A legacy [database] or [images] section is still read but ignored in server mode: databases come from the registry.

Preview format

Previews and annotated images are PNG by default: exact, the same pixels the stretch made. preview_format = "jpeg" makes them about a third the size, but JPEG smooths the faint detail where noise, hot pixels and marginal stars live, so a frame can look cleaner than it is. Grading always measures the FITS, never a preview. The two formats use different extensions, so switching back finds the old files still valid. Nothing deletes the other format; the server reports its size at start.

preview_color sets which rendition of a one-shot-color frame pre-generation warms and the viewer opens with.

Grant remote sync and uploads in the file

A server run from the command line has no Settings panel, so it takes remote grants from its config file:

[[remote_sync]]
database = "telescope"                       # registry slug
token_file = "/run/secrets/psf-guard-key"    # or token = "..."

[[remote_upload]]
database = "telescope"
image_dir = "/data/incoming"
placement = "target_tree"                    # optional; default "flat"
#directory_template = "%YEAR%/%TARGET%/%NIGHT%/%TYPE%"
token_file = "/run/secrets/psf-guard-key"

These apply at start and are never written back to the registry, so rotating a key is a restart. A database has one key, whatever it grants. Naming a database that is not registered stops the server. Neither block needs --allow-database-management. Template tokens: %PROJECT%, %TARGET%, %DATE%, %NIGHT%, %YEAR%, %TYPE%, %FILTER%, %TELESCOPE%, %CAMERA%, %EXPOSURE%, %GAIN%. See Rejects & Sync and N.I.N.A. Sync Plugin.

Fill in GUIDs

Planning, sync and multi-rig projects find Target Scheduler rows by GUID. Target Scheduler skips giving existing rows one when a database is upgraded past schema 22 in one step, and such projects cannot be planned or synced. Settings → Databases says how many rows lack one and offers Fill in GUIDs. It copies the database beside itself first, then fills only the empty GUIDs. Close N.I.N.A. on that rig before filling.

psf-guard -d schedulerdb.sqlite fill-guids --dry-run
psf-guard -d schedulerdb.sqlite fill-guids

REST API

Per-database routes sit under /api/db/{db_id}/. GET /api/databases lists the databases and their IDs. On a server with accounts, send a session cookie or an API token; see Server Accounts. Agents can use the MCP endpoint instead.

# List images with filters
curl "localhost:3000/api/db/my-db/images?project_id=2&status=pending"

# Set a grade
curl -X PUT localhost:3000/api/db/my-db/images/123/grade \
  -H "Content-Type: application/json" \
  -d '{"status": "accepted"}'

# Start and read a quality scan
curl -X POST localhost:3000/api/db/my-db/analysis/quality-scan \
  -H "Content-Type: application/json" \
  -d '{"target_id": 42}'
curl localhost:3000/api/db/my-db/analysis/quality-scan

# Processed images
curl "localhost:3000/api/db/my-db/images/123/preview?size=large" -o preview.png
curl "localhost:3000/api/db/my-db/images/123/annotated" -o stars.png

# Catalog capabilities and on-demand plate solving
curl "localhost:3000/api/astrometry/capabilities"
curl "localhost:3000/api/db/my-db/images/123/astrometry"
curl -X POST "localhost:3000/api/db/my-db/images/123/astrometry"

# Cached or on-demand satellite prediction
curl "localhost:3000/api/db/my-db/images/123/satellites"
curl -X POST "localhost:3000/api/db/my-db/images/123/satellites"

# Processor shares and storage
curl localhost:3000/api/settings/workers
curl localhost:3000/api/settings/storage

# The job queue
curl localhost:3000/api/stack-activity
  • A preview or annotated image not yet cached answers 202 with {"state": "generating"}. Poll the batch generation-status route to learn when it is ready.
  • The quality scan measures spatial and photometric evidence and solves each frame from its pixels; sequence analysis reads the results. See Astrometry Quality.
  • Exports have three routes: a ZIP download, a write to any server path (needs database management), and GET/POST /api/db/{db_id}/export/server, which writes only below export_dir and reports progress. See Export & AstroBin.
  • Database management routes such as POST/PUT/DELETE /api/databases are off unless the server starts with --allow-database-management. The desktop app always turns them on for its own local server.

Known limitations

  • One-shot-color frames are measured on luminance. The viewer shows a raw OSC frame with a BAYERPAT header in colour (C switches to luminance), but grading and quality metrics always use luminance, so the numbers stay comparable with N.I.N.A.'s.
  • Folder layouts. Layouts like %DATEMINUS12%/%TARGETNAME%/%DATEMINUS12%/LIGHT/..., with or without the leading date, are recognized. For others, open an issue with an example.
  • Back up first. Back up a catalog before bulk edits, and your image files before commands that move them.
