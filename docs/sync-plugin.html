N.I.N.A. Sync Plugin

PSF Guard Sync connects a live Target Scheduler catalog to a PSF Guard server. It can upload saved lights and calibration frames, push scheduler captures, and exchange plans and reviewed grades. You do not need to run CLI sync commands between two database files.

Beta channel, working end to end. Current builds pair with a one-time code, upload FITS or XISF images, and move Target Scheduler data through the versioned /api/sync/v1 protocol. Older 0.6.1+ servers and clients can still use the manual API-key setup below.

Install it in N.I.N.A.

PSF Guard hosts its own N.I.N.A. plugin repository. Add it as a plugin source and PSF Guard Sync installs and updates like any other plugin:

  1. In N.I.N.A., open Options → Plugins.
  2. Add this repository URL: 
    https://nina-plugins.psf-guard.com/
  3. Turn on “Include beta versions” — PSF Guard Sync ships on the beta channel.
  4. Find PSF Guard Sync in the Available list, install it, and restart N.I.N.A.
Requires Windows x64, N.I.N.A. 3.2.0.9001 or newer, and PSF Guard 0.6.1+. Target Scheduler schema 22+ is required for catalog sync, but not for direct FITS upload. The registry lives at nina-plugins.psf-guard.com.

Pair N.I.N.A. with a catalog

  1. Open Settings → Databases and edit the destination catalog.
  2. If N.I.N.A. will upload image files, enable Remote image uploads, choose one configured image directory as the receive directory, and save the catalog.
  3. Choose Generate pairing code beside Pair a client, then copy the code.
  4. In the plugin, enter the PSF Guard server URL, paste the pairing code, and connect. The server returns the catalog ID and a credential for this N.I.N.A. install in one step.
  5. Run Test connection, then choose the upload and catalog sync behavior you want.

A pairing code works once and expires after one hour. Each successful pairing creates a separate catalog-scoped credential. PSF Guard stores only its digest, and the plugin stores the credential in Windows Credential Manager. Pairing enables scheduler sync for that catalog. It does not enable image upload or choose a receive directory.

The same catalog editor shows Paired clients. Revoke one install there without disconnecting any other paired client.

Creating a pairing code and revoking a client are database-management actions. A browser-managed server needs database management enabled and an editor login. See Server Accounts for the network-server access model.

Manual API-key fallback

A client that does not support pairing can still use the original setup:

  1. Enable Remote scheduler sync on the catalog. Enable Remote image uploads separately when needed.
  2. Choose Generate beside Remote API key, copy the key while it is visible, and save the catalog.
  3. Copy the catalog ID from the database list or its ?db= URL, then enter the URL, ID, and key in the client.

Replacing this manual key invalidates the previous manual key. It does not revoke paired clients. Revoking a paired client likewise leaves the manual key and other clients working.

How it works

The plugin listens for N.I.N.A.'s image-saved event and supports two capture paths. Direct image mode queues the saved FITS or XISF file. Target Scheduler mode waits for the light's matching acquiredimage row, then queues a bundle that preserves the capture, project, target, and plan fields. Uploads run in the background. If the server is unavailable, the work stays in the retry queue.

  • Direct image upload — send FITS or XISF lights, bias frames, darks, dark-flats, and flats without installing Target Scheduler. Calibration frames enter PSF Guard's calibration library and never create Target Scheduler image rows.
  • Automatic catalog push — queue each light after Target Scheduler records it, including the scheduler metadata PSF Guard needs to preserve the plan.
  • Durable retry queue — bundles stay under %LOCALAPPDATA%\NINA\PsfGuardSync and survive restarts. Retrying the same basename and digest does not create another catalog entry.
  • Background previews — large catalog pushes create their preview as a background job. The plugin checks progress with a job-specific token. This prevents reverse-proxy timeouts.
  • Two-way, on demand — manual full merge, planning push, and reviewed-grade push, plus planning and grade pull back into Target Scheduler.
  • Stable identity — images match by GUID. PSF Guard updates parent IDs for projects, targets, templates, and plans while preserving the telescope's acquired and accepted counters. Grade pulls change only gradingStatus and rejectreason.
  • Optional thumbnails — transfer Target Scheduler thumbnails alongside the capture.
  • Verified pulls — PSF Guard sends a SHA-256 hash of the exact response body in X-Content-SHA256. The plugin checks this hash before changing Target Scheduler. It does not rely on the digest inside the JSON bundle because JSON encoders can represent the same data with different bytes.

Review staged catalog changes

Every catalog push creates a server-owned preview before it can write the destination. Open Settings → Sync and find Staged previews. The list includes previews made in this browser and previews a remote N.I.N.A. client left for review.

Each row names the catalog, operation, source, change counts, and expiry. Expand What would change to see each field change. The list includes grade transitions and their reasons, plus each project, target, plan, or image that will be inserted or updated. It shows at most 400 lines.

  • Apply writes the reviewed preview.
  • Refresh compares the saved source bundle with the destination again. Use it after the destination changed.
  • Discard removes the staged preview without changing the catalog.
Nothing changes until Apply. If automatic apply is enabled, the plugin applies the exact preview it just created. Otherwise, the preview waits for review until you apply, discard, or let it expire.

Choose sync and upload behavior

After pairing, open Plugins → Installed → PSF Guard Sync and choose:

  1. For catalog sync, the Target Scheduler database path (default %LOCALAPPDATA%\NINA\SchedulerPlugin\schedulerdb.sqlite).
  2. Whether to upload each saved light directly.
  3. Whether to also upload calibration frames: bias, dark, dark-flat, and flat saves.
  4. Whether to push each saved light's Target Scheduler row.
  5. Whether catalog previews should apply automatically or wait in PSF Guard for review.

Use Test connection before enabling automatic work. It checks the URL, paired or manual credential, selected catalog, protocol version, and server grants.

Sequencer instructions

The plugin also contributes instructions under PSF Guard Sync in the advanced sequencer:

  • Check PSF Guard connection — verifies the server, credential, and selected catalog. Place it near the start of a session. If the server is unavailable, the sequencer uses the instruction's configured error handling.
  • Pull PSF Guard planning — applies remote projects, targets, templates, and plans to Target Scheduler. Run it before a Target Scheduler container starts; a running container may keep its in-memory plan.
  • Pull PSF Guard grades — applies reviewed grades and rejection reasons by unambiguous acquired-image GUID.
  • Reconcile PSF Guard catalog — pushes a fresh full scheduler snapshot, waits for PSF Guard's preview, and optionally applies it. This is useful at the end of a session.
  • Reconcile current target with PSF Guard — does the same for only the enclosing target. Place it near the end of that target's container; ambiguous Target Scheduler target names are refused instead of guessed.
  • PSF Guard image upload — waits for the completed save, then uploads the selected lights, calibration frames, or both. It works without Target Scheduler and can replace profile-wide automatic uploads for one sequence.

Reconciliation waits for Target Scheduler to finish its transaction and for the server to create the preview. The sequence does not continue until both steps finish. Automatic per-capture pushes continue retrying in the background.

Troubleshooting

ResultCheck
Pairing code is unknown, expired, or already usedGenerate a new code from the destination catalog. A code works once and lasts one hour.
401 or “Bearer token required”The plugin has no saved credential, or its paired client was revoked. Pair it again, or configure the manual key fallback, then run Test connection.
403 invalid key or wrong catalogA credential is catalog-scoped. Pair with the intended catalog, or confirm both the manual key and catalog ID.
403 scheduler sync disabledEnable Remote scheduler sync on that PSF Guard catalog. Image upload permission alone does not grant catalog changes.
Image upload is unavailableEnable Remote image uploads and choose a receive directory on that catalog. Pairing does not enable this separate grant.
404 under /api/sync/v1Upgrade the PSF Guard server to 0.6.1 or newer. A 404 for an older preview can also mean its 30-minute lifetime ended or it was already applied.
Large preview times out at a proxyUpgrade both sides so the client requests background preview jobs and polls them to completion.
“Bundle digest is missing or invalid”Upgrade both sides so pulls verify the raw response against X-Content-SHA256 instead of re-serializing the JSON bundle.
Queued work does not drainRun Test connection, confirm N.I.N.A. can reach the server URL, then leave the plugin running; its durable queues resume automatically.
Working from one machine, or syncing two SQLite files directly? The CLI psf-guard sync commands do the same job between database files, without the plugin.
