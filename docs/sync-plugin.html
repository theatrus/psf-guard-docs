N.I.N.A. Sync Plugin

The PSF Guard Sync plugin connects N.I.N.A. and its Target Scheduler catalog to a PSF Guard server. It uploads saved lights and calibration frames, pushes scheduler captures, and pulls plans and reviewed grades back, so nobody copies database files by hand.

The plugin ships on N.I.N.A.'s beta channel. It pairs with a one-time code, uploads FITS or XISF files, and moves Target Scheduler data over the versioned /api/sync/v1 protocol. Servers and clients from 0.6.1 on also accept the manual API key described below.

Install the plugin

PSF Guard hosts a N.I.N.A. plugin repository. Add it once, and the plugin installs and updates from within N.I.N.A.:

  1. In N.I.N.A., open Options → Plugins.
  2. Add this repository URL: 
    https://nina-plugins.psf-guard.com/
  3. Turn on Include beta versions.
  4. Find PSF Guard Sync, install it, and restart N.I.N.A.
The plugin needs Windows x64, N.I.N.A. 3.2.0.9001 or newer, and PSF Guard 0.6.1 or newer. Catalog sync needs Target Scheduler schema 22 or newer; direct image uploads do not. The repository lives at nina-plugins.psf-guard.com.

Pair N.I.N.A. with a catalog

  1. In PSF Guard, open Settings → Databases and edit the destination catalog.
  2. To receive image files, tick Accept remote image uploads, choose a Receive directory from the catalog's image folders, and pick a Folder layout: Receive directory keeps every upload in that folder; Match catalog files each one into folders laid out like the rest of the catalog. Save the catalog.
  3. Click Generate pairing code beside Pair a client, and copy the code.
  4. In the plugin, enter the PSF Guard server URL, paste the code, and connect. The server returns the catalog ID and a credential for this N.I.N.A. installation.
  5. Click Test connection, then choose what to upload and sync.

A pairing code works once and expires after an hour. Each pairing makes its own catalog-scoped credential: the server keeps only its digest, and the plugin keeps it in Windows Credential Manager. Pairing turns on scheduler sync for the catalog. It does not turn on image uploads or choose the receive directory.

Paired clients, in the same editor, lists each connected installation. Revoke cuts off one installation and leaves the others alone.

Generating pairing codes and revoking clients manage the database, so a server needs database management, and with accounts an editor login. See Server Accounts.

Use a manual API key

For a client that cannot pair:

  1. Edit the catalog and click Generate beside Remote API key. Copy the key now: it is not shown again after saving.
  2. Tick Accept remote scheduler sync, and Accept remote image uploads to receive files. Save the catalog.
  3. Copy the catalog ID from the database list or its ?db= URL. Enter the server URL, the database ID and the key in the plugin.

A new manual key replaces only the previous manual key. Paired clients keep working, and revoking a paired client leaves the manual key alone.

How the plugin works

The plugin listens for N.I.N.A.'s image-saved events and has two capture paths. Direct image mode queues the saved FITS or XISF file for upload. Target Scheduler mode waits for the matching acquiredimage row, then queues a bundle with the capture metadata, project, target and plan. Uploads run in the background. If the server is offline, the plugin keeps the queue and retries later.

  • Direct uploads need no Target Scheduler. Lights, bias, darks, dark-flats and flats upload as FITS or XISF. Calibration frames, twilight flats included, go to the PSF Guard calibration library and never become Target Scheduler rows.
  • Catalog pushes follow each light. Once Target Scheduler records a light, the plugin queues it with the scheduler metadata PSF Guard needs to rebuild the plan.
  • The queue survives restarts. Queued bundles live under %LOCALAPPDATA%\NINA\PsfGuardSync. A retry with the same file name and hash does not add a second catalog entry.
  • Large previews run in the background. The server builds a catalog preview as a job, and the plugin polls it with a job-specific token, so a reverse proxy never times out.
  • Transfers go both ways. Merge, push plans and push grades on demand, and pull plans and grades back into Target Scheduler.
  • Frames match by GUID. PSF Guard updates parent IDs for projects, targets, templates and plans and keeps the telescope's capture counts. Pulling grades changes only gradingStatus and rejectreason.
  • Thumbnails are optional. The plugin can send Target Scheduler's thumbnails with the capture data.
  • Pulls are checked. PSF Guard sends the SHA-256 of each response body in an X-Content-SHA256 header, and the plugin checks it before changing Target Scheduler.

What the server does with an upload

  • It writes the file to a temporary name, checks its SHA-256 and headers, and publishes it without overwriting anything.
  • A light joins an existing target by name or coordinates, as a folder import does, or the row scheduler sync already made for it. A light with no match builds its project, target, template and plan from its headers.
  • Analyze new frames as they arrive, a per-database option beside the quality backfill buttons, scores uploaded and synced frames in the background. See Quality Screening.
  • With Rebuild stack previews on their own on, new frames queue a stack refresh. See Storage & Performance.
  • keep_failed_uploads = true in the server's [server] config keeps a refused upload's staged file, and the log names it, to show what the client sent.

Review staged catalog changes

Each catalog push makes a preview on the server before anything changes. Settings → Sync → Staged previews lists them, including those from remote N.I.N.A. installations, with the catalog, operation, source, change counts and expiry. Expand What would change for the field changes and grade transitions, up to 400 lines.

  • Apply writes the changes to the destination.
  • Refresh compares the bundle with the destination again, after the destination changed.
  • Discard deletes the preview and changes nothing.
Nothing changes until a preview is applied. With automatic apply on in the plugin, the plugin applies each preview at once. Otherwise the preview waits until you apply it, discard it, or it expires after 30 minutes.

Configure the plugin

After pairing, open Plugins → Installed → PSF Guard Sync in N.I.N.A.:

  1. Set the Target Scheduler database file path. The default is %LOCALAPPDATA%\NINA\SchedulerPlugin\schedulerdb.sqlite.
  2. Choose whether to upload each saved light.
  3. Choose whether to also upload calibration frames: bias, darks, dark-flats and flats.
  4. Choose whether to push each light's Target Scheduler row.
  5. Choose whether catalog previews apply on their own or wait for review in PSF Guard.

Click Test connection before turning on automatic work. It checks the server URL, credential, catalog, protocol version and permissions.

Use the sequencer instructions

The plugin adds a PSF Guard Sync category to N.I.N.A.'s advanced sequencer:

InstructionWhat it does
Check PSF Guard connectionChecks the server URL, credential and catalog. Place it near the start; an offline server triggers the sequence's error handling.
Pull PSF Guard planningPulls projects, targets, templates and exposure plans into Target Scheduler. Run it before a Target Scheduler container starts, since a running container may not reload plans from disk.
Pull PSF Guard gradesPulls reviewed grades and reject reasons, matched by image GUID.
Reconcile PSF Guard catalogUploads a full Target Scheduler snapshot, waits for the preview, and can apply it. Use it at the end of a session.
Reconcile current target with PSF GuardReconciles the current target only. Place it near the end of the target's container. The server refuses targets whose names are not unique.
PSF Guard image uploadWaits for the current image write, then uploads the chosen light or calibration frames. Works without Target Scheduler and overrides the profile's upload settings for one sequence.

Reconcile instructions pause the sequence until Target Scheduler finishes its database write and the server finishes the preview. Per-capture uploads carry on in the background and retry on errors.

Fix common problems

ResultCheck
Pairing code is unknown, expired, or already usedGenerate a new code on the destination catalog. A code works once, for one hour.
401 or “Bearer token required”The plugin has no saved credential, or its client was revoked. Pair again, or set the manual key, and run Test connection.
403 invalid key or wrong catalogCredentials belong to one catalog. Pair with the intended catalog, or check both the manual key and the catalog ID.
403 scheduler sync disabledTick Accept remote scheduler sync on that catalog. Upload permission alone does not grant catalog sync.
Image upload unavailableTick Accept remote image uploads and choose a Receive directory. Pairing does not turn uploads on.
404 under /api/sync/v1Upgrade PSF Guard to 0.6.1 or newer. For a preview, a 404 can also mean its 30 minutes ran out or it was already applied.
Large preview times out at a proxyUpgrade the plugin and server, so the plugin starts a background preview job and polls it.
“Bundle digest is missing or invalid”Upgrade both, so pulls check the raw response against X-Content-SHA256 instead of re-serializing the JSON.
Queued work does not drainRun Test connection, check that N.I.N.A. reaches the server URL, and leave the plugin running. The queues resume when the connection returns.
To sync two SQLite files, or two PSF Guard servers, without the plugin, use Rejects & Sync.
